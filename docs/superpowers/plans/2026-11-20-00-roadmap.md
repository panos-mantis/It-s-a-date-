## Branches

- `main`: what's live on Render today. It only receives the Phase 0 hotfix until cutover.
- `modernize`: the integration branch, created from `main` at `fbae295` after Phase 0 merged (exists on GitHub).
- **Never check out a commit from before Phase 0 (`e1cf2fe` or older) in the working copy.** Those commits still track `Its a date BACKEND/.env` and `node_modules`, so a checkout overwrites the local ignored `.env`, and moving forward again deletes it. This happened once, on 2026-11-22. To update a stale local branch, use `git fetch` then `git branch -f <name> origin/<name>`.
- `phase-N-<name>`: one branch per phase, cut from `modernize` and merged back by PR after review.
- Cutover (Phase 7) merges `modernize` into `main`.

Each is written with superpowers:writing-plans as soon as its dependencies are merged. The spec already fixes their scope.

## Acceptance per phase (from the spec)

- **0:** no secrets or `node_modules` tracked; live API rejects unauthenticated admin actions with 401/403; admin self-registration gone; exactly one admin in prod; dev DB `itsadate_dev` exists and the local `.env` uses it.
- **1:** `npm ci && npm run ci` passes at the root (lint, typecheck, test, build for all workspaces); CI green on GitHub; `packages/shared` exports every schema/type listed in Phase 1 Task 2.
- **2:** all API routes in spec §8.3 exist under `/api/v1` with Zod validation, cookie auth and role checks; integration tests cover each route's success path plus 401/403/422; `migrate --dry-run` against a copy of prod reports the planned changes and a real run is idempotent; `seed` loads about 30 ideas (at least 3 per tag); `create-admin` works.
- **3:** Vite app with Tailwind tokens mapped 1:1 from `DESIGN.md`; UI kit components with tests; login, signup and logout working against the Phase 2 API (or MSW mocks if 2 isn't merged yet).
- **4:** Home, Idea detail, Share an idea, Auth, Profile and Admin screens (desktop + phone) in `.open-design/`, each passing checks and the critic; owner signs off Home and Idea detail.
- **5:** every page in spec §8.4 built from its approved design; loading, empty and error states; axe-clean.
- **6a/6b:** spec §8.3 rating/save endpoints and §8.6 places behaviour, with tests; UI per the designs.
- **7:** spec §8.5 and §8.8 delivery; cutover runbook executed with a backup; live site serves the new app; README, ADRs and Playwright smoke test done.

# Phase 2 — API Rebuild Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the legacy Express 4 API with the layered TypeScript Express 5 API in `apps/api`: hardened app shell, Mongoose models, cookie auth with roles, tags, ideas (public, user, admin), admin users, plus the `create-admin`, `migrate` and `seed` scripts. All of it is test-first against an in-memory MongoDB.

**Architecture:** Feature folders under `apps/api/src/features/<name>/`, each holding `<name>.routes.ts → <name>.controller.ts (HTTP only) → <name>.service.ts (rules) → <name>.repository.ts (Mongoose)`. Cross-cutting code sits in `config/`, `lib/`, `middleware/`, `db/`, `models/`. Every input is parsed by `validate()` with a schema from `@itsadate/shared`, and every response uses the shared DTOs. Scripts are thin CLIs over tested functions.

**Tech Stack:** Express 5, Mongoose 8, Zod 4 (via `@itsadate/shared`), `bcryptjs` (pure JS, reads the legacy `$2b$` hashes), `jsonwebtoken`, `cookie-parser`, `helmet`, `cors`, `express-rate-limit`, `pino` + `pino-http`, Vitest + Supertest + `mongodb-memory-server`, `@vitest/coverage-v8`, `tsx` for scripts. Use the latest stable release of each (Mongoose: latest 8.x) at install time.

**Spec:** `docs/superpowers/specs/2026-11-20-its-a-date-modernization-design.md` §8.2, §8.3 (and §8.5 for the image-ownership rule only)

## Scope

**In:** spec §8.3 routes for auth, ideas, `GET /me/ideas`, tags, admin ideas, admin tags, admin users. All five data models, including `Rating` and `Save`, because the seed writes ratings and saves and `IdeaDTO` carries `myRating` and `saved`. Hardening, env validation, migration, seed, create-admin. Deleting `apps/api/legacy/`.

**Out (other phases, per spec §8.9):** `PUT/DELETE /ideas/:id/rating`, `PUT/DELETE /ideas/:id/save` and `GET /me/saved` (Phase 6a). `GET /places` (6b). `POST /uploads/image`, Cloudinary SDK, asset deletion and all photos (Phase 7). Seeded and migrated ideas get `image: null` in Phase 2, and Phase 7 fills them in. Migrated ideas keep their `_id`, so Phase 7's photo list can key on it.

**Added beyond §8.3 (needed by the spec's Admin "users" page):** `GET /admin/users`.

## Global Constraints

- Branch `phase-2-api`, cut from local `modernize`. The PR goes into `modernize`.
- Never check out a commit from before Phase 0 (`e1cf2fe` or older). Never read, print, stage or delete any `.env`. Tests and dev never touch the database `ItsADate`.
- ESM, TypeScript strict (inherits `tsconfig.base.json`). Imports use `.js` suffixes.
- Contract names from `packages/shared` are binding. New shared exports are only the ones Tasks 1, 4 and 7 list.
- Error body is always `ApiErrorBody`: `{ error: { code, message, details? } }`. Status ↔ code: 400 `BAD_REQUEST`, 401 `UNAUTHORIZED`, 403 `FORBIDDEN`, 404 `NOT_FOUND`, 409 `CONFLICT`, 413 `BAD_REQUEST`, 422 `VALIDATION`, 429 `RATE_LIMITED`, 500 `INTERNAL`.
- Response conventions: a single resource → its DTO. Unpaginated list → a bare array (`TagDTO[]`). Paginated list → `Paginated<T>`. Create → 201. Delete or logout → 204 with no body.
- Never return or log `passwordHash`, `JWT_SECRET`, cookies or the Mongo URI. pino redacts `req.headers.cookie`, `req.headers.authorization` and `res.headers["set-cookie"]`.
- Session cookie: name `itsadate_session`, `httpOnly`, `sameSite: 'lax'`, `secure` only when `NODE_ENV=production`, `path: '/'`, `maxAge` 7 days. JWT: HS256, payload `{ sub: userId, role }`, `expiresIn: '7d'`, verified with `algorithms: ['HS256']`.
- bcrypt cost 12 for new hashes. Existing hashes (cost 10) stay valid.
- Workspace scripts run as `npm run <x> -w @itsadate/api`. `-w api` from the spec doesn't resolve, so `@itsadate/api` is the form to use.
- Windows dev machine: no POSIX-only syntax in npm scripts.
- Every admin route has a 401 test (no cookie) and a 403 test (user cookie). Every route with input has a 422 test.
- Commit trailer on every commit: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

- **Re-running the migration after go-live work:** the owner runs `migrate`, then `create-admin`, then (by mistake or in a rehearsal) `migrate` again. The second run must not demote the new admin, resurrect a deleted idea, or undo admin edits. Pinned in Task 9 (`does not demote admins or resurrect ideas on re-run`).
- **Search text with regex characters:** `GET /ideas?q=(` or `q=.*` must be matched literally: 200, no 500, and no match-everything. Pinned in Task 5 (`treats q as literal text`).
- **A stale session after a role change:** an admin is demoted (or their account deleted) while their 7-day cookie is still valid. Their next admin request must get 403 (or 401), not succeed on the role baked into the JWT. Pinned in Task 7 (`demoted admin's existing cookie loses admin access`).
- **An expired or garbage cookie on a public page:** `GET /ideas` and `GET /ideas/:id` with a bad cookie must answer as anonymous (200), not 401. Otherwise, a logged-out browser with an old cookie sees an error on the home page. Pinned in Task 5 (`ignores an invalid session cookie on public routes`).
- **Duplicate legacy emails that differ only by case or whitespace:** `Ana@X.com `, `ana@x.com` and `ANA@x.com` are one person. The migration merges them into the oldest account, and that account logs in with its original password afterwards. Pinned in Task 9 (`merges case-variant duplicates and keeps the oldest password`).

**Interfaces:**
- Produces:
  - `envSchema`, `type Env`, `loadEnv(source?: NodeJS.ProcessEnv): Env` (throws `Error` whose message lists the invalid keys but never their values), `loadDotEnvFile(path = '.env'): void` (calls `process.loadEnvFile(path)` only if the file exists).
  - `Env` keys: `NODE_ENV` (`development|production|test`, default `development`), `PORT` (int, default 4000), `MONGODB_URI` (required, must name a database; database `ItsADate` is rejected unless `NODE_ENV=production`), `JWT_SECRET` (min 32 chars, rejects `.env.example`'s placeholder), `CORS_ORIGINS` (comma list → `string[]`, default `['http://localhost:5173']`), `TRUST_PROXY` (int ≥0, default 0), `LOG_LEVEL` (pino level, default `info`), `DNS_SERVERS` (optional comma list → `string[] | undefined`), `AUTH_RATE_LIMIT_MAX` (int, default 20), `CLOUDINARY_CLOUD_NAME` (optional), and a derived `CLOUDINARY_FOLDER` (`itsadate/prod` in production, else `itsadate/dev`).
  - `mongoDbName(uri: string): string` (`''` if none) in `config/env.ts`, which the scripts reuse.
  - `class AppError extends Error { status: number; code: ApiErrorCode; details?: unknown }` and the factories `badRequest(msg)`, `unauthorized(msg = 'Please log in')`, `forbidden(msg = "You don't have access to this")`, `notFound(msg = 'Not found')`, `conflict(msg)`, `validationError(details: ValidationErrorDetails, msg = 'Check the highlighted fields')` in `lib/errors.ts`.
  - `createLogger(env: Env): pino.Logger` (level `silent` when `NODE_ENV=test`).
  - `validate(schemas: { body?: ZodType; query?: ZodType; params?: ZodType }): RequestHandler`. It stores parsed output in `res.locals.validated.{body,query,params}` and never writes to `req.query`. Controllers read `res.locals.validated.<part>` and cast it to the schema's output type.
  - `errorHandler: ErrorRequestHandler`. Mapping: `AppError` → its own status. body-parser `entity.parse.failed` → 400 `BAD_REQUEST` "Malformed JSON". `entity.too.large` → 413. Mongoose `CastError` → 400. Mongo duplicate key (code 11000) → 409 `CONFLICT` "Already exists". Anything else → 500 `INTERNAL` "Something went wrong", logged with the request id, with no stack in the body.
  - `createApp(deps: { env: Env; logger?: pino.Logger }): Express`. It sets `trust proxy` = `env.TRUST_PROXY`, then helmet, CORS (allow-list, `credentials: true`), `pino-http` (request id from a valid incoming `x-request-id` (≤64 chars, `[\w-]`) or `randomUUID()`, echoed in the `x-request-id` response header), `express.json({ limit: '100kb' })`, `cookie-parser`, `/healthz`, the `/api/v1` router, the JSON 404, then `errorHandler`.
  - `express.d.ts` augments `Express.Locals` with `validated: { body?: unknown; query?: unknown; params?: unknown }` and `auth?: AuthContext`, where `AuthContext = { userId: string; role: Role }` is exported from `types/auth.ts`.
  - Shared `dto.ts` gains `ValidationIssue { location: 'body' | 'query' | 'params'; path: string; message: string }` and `ValidationErrorDetails { issues: ValidationIssue[] }`. `path` is dot-joined (`image.url`), and is `''` for the root.
  - `testEnv(overrides?: Partial<Env>): Env` in `src/test/env.ts`, with a fixed 40-char secret, `NODE_ENV: 'test'` and a placeholder Mongo URI.
  - api `package.json`: `lint` = `eslint .`; `test` = `vitest run --coverage` (provider v8, reporter `text-summary`, coverage on `src/**`, excluding `src/test/**` and `src/scripts/**`).

**Files:**
- Create: `apps/api/src/migrate/{migrate,legacy-tags}.ts`, `apps/api/src/scripts/migrate.ts`
- Modify: `apps/api/package.json` (script `migrate`)

**Interfaces:**
- Consumes: `slugify`, `allModels`, `parseArgs`, `resolveTarget`, `confirmTarget`, `connectDb`.
- Produces:
  - `legacy-tags.ts`: `LEGACY_TAG_DEFAULTS: Record<string, { icon: string; placeType: PlaceType }>`, keyed by slug, for the 8 live tags (`food` utensils/restaurant, `adventure` mountain/park, `home` house/none, `self-date` heart/none, `board-game` dice-5/none, `dancing` music/none, `self-care` flower-2/spa, `learning` book-open/museum). Any other slug gets `{ icon: 'sparkles', placeType: 'none' }`.
  - `runMigration(db: mongodb.Db, opts: { dryRun: boolean }): Promise<MigrationReport>`. It uses the raw collections because the legacy shapes don't fit the models. `MigrationReport = { tags: { converted; created; merged }; users: { converted; merged; deleted; demoted }; ideas: { converted; approved; pending; legacyCollectionRenamed: boolean }; indexesSynced: boolean; dryRun: boolean }`. A dry run computes the same report and writes nothing.
  - Steps, in order. Each step only touches documents still in legacy shape:
    1. **Tags.** Docs with `tagName` get `name = tagName`, `slug = slugify(tagName)`, `icon` from defaults, `$unset tagName`. Docs that share a slug merge into the oldest `_id`. Any tag string used in `dates.tags` with no tag doc gets a new tag.
    2. **Users.** Only docs with `password` or `isAdmin` present (legacy shape) are converted. `email` is trimmed and lowercased. `passwordHash = password`, `role: 'user'`. `password`, `isAdmin` and `personalRates` are unset. `createdAt`/`updatedAt` come from `_id.getTimestamp()` if missing. Users are then grouped by normalized email; the oldest `_id` is kept, the duplicates' `dates.creator` / `ideas.creator` are re-pointed to it, and the duplicates are deleted. Docs that already have `role` and no legacy fields are never touched (so an admin created after the first run stays admin).
    3. **Ideas.** If `dates` exists: each doc is written to `ideas` with the **same `_id`**, using `insertOne`, and skipped when the `_id` already exists. Fields: `title = tittle`, `description = text`, `status = review ? 'approved' : 'pending'`, `tags` = ObjectIds by slug of each name, `placeType` = the first tag's default, `image: null`, `budget: null`, `duration: null`, `ratingAvg/ratingCount/saveCount: 0`, `creator` (re-pointed if merged), and timestamps from `_id`. Then `dates` is renamed to `legacy_dates` (or `legacy_dates_<YYYYMMDDHHmmss>` if that name is taken, e.g. after a fresh prod→dev copy), so a re-run finds nothing to convert and never resurrects deleted ideas.
    4. **Indexes.** `syncIndexes()` on every model; this builds the unique email index after the dedupe.
  - CLI `npm run migrate -w @itsadate/api -- [--dry-run] [--db <name>]`: resolves and confirms the target (a dry run skips confirmation, even on prod), connects, prints the report as JSON. Adding `--verbose` also lists each tag with its slug, icon and placeType, and each merged email group as a count only (no addresses).
